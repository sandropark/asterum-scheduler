# Asterum-scheduler

## AI 활용

AI 활용 범위: 설계 및 의사결정 시 의견을 구함. 그렇게 작성한 설계 문서를 바탕으로 대부분의 코드 작성을 위임.

주요 논의 내용: AI와 논의 한 설계 중 어떤 것을 수용하고 어떤 것을 반려헀나요? 각각의 이유를 알려주세요
    - 수용
      - isFirst 대신 eventStartAt를 응답으로 포함: 백엔드가 UI 개념("첫 번째")을 알 필요 없음. 프론트가 instance.startAt == eventStartAt으로 파생 가능하고 재활용성
    - 반려
      - 단일 일정 -> 반복 일정 변경 시 기존에 구현된 단일 일정 전용 메서드를 수정하도록 AI가 제안했지만 프론트에서 분기로 updateAllTime를 호출하면 백앤드 수정 없이 재활용 가능해서 반려
검토 및 수정 과정: AI가 제안한 결과물 중 오류가 있었거나, 직접 보완한 지점이 있다면 기술해 주세요.
    - 반복 일정 수정 엣지 케이스 발견: AI 제안이 아닌 직접 질문으로 "5/2 선택 후 전체 수정 COUNT=3 → 5/1,5/2,5/3인가 5/2,5/3,5/4인가?"를 제기해 updateAllTime의 시작 날짜 사이드이펙트를 식별. 이후 설계 결정(날짜 고정)으로
  이어짐
    - updateTitleThisAndFuture 설계 재검토: AI가 제시한 "이벤트 분리" 구현이 정확히 동작했지만, "제목만 바꾸는데 이벤트 분리까지 하는 게 과하다"는 제품 관점 판단으로 단순화 요구 → AI가 코드 축소 진행
